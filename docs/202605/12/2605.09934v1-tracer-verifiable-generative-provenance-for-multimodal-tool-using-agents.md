## 摘要
多模态大语言模型越来越多地通过调用外部工具进行视觉检查、OCR、检索、计算和多步推理来解决以视觉为中心的任务。目前的工具使用智能体通常会公开执行的工具轨迹和最终答案，但它们很少指明哪项工具观察结果支持了每个生成的断言。我们将这种缺失的断言级依赖结构称为“溯源鸿沟”（provenance gap）。这一鸿沟使得工具使用难以验证且难以优化，因为有用的证据、冗余的探索和无支撑的推理都混合在同一轨迹中。我们提出了 TRACER，这是一个用于多模态工具使用智能体的可验证生成式溯源框架。TRACER 并非在生成后添加引用，而是在生成每个答案句子的同时，生成一个结构化的溯源记录，该记录识别了支撑工具轮次、证据单元和语义支撑关系。其关系空间包含引用（Quotation）、压缩（Compression）和推理（Inference），涵盖了直接重用、忠实浓缩和有据推导。TRACER 通过模式检查、工具轮次对齐、来源真实性和关系合理性来验证每条记录，然后将验证后的溯源转化为可追溯性约束和基于溯源的局部信用（local credit），用于强化学习。我们进一步构建了 TRACE-Bench，这是一个用于从粗粒度多模态工具轨迹中进行句子级溯源重建的基准测试。在 TRACE-Bench 上，单纯增加工具往往会引入噪声。使用 Qwen3-VL-8B，TRACER 达到了 78.23% 的答案准确率和 95.72% 的摘要准确率，比最强的闭源工具增强基线高出 23.80 个百分点。与仅使用工具的监督微调相比，它还将测试集总工具调用次数从 4949 次减少到 3486 次。这些结果表明，可靠的多模态工具推理取决于对观察结果的溯源感知使用，而不仅仅是增加工具调用次数。

## Abstract
Multimodal large language models increasingly solve vision-centric tasks by calling external tools for visual inspection, OCR, retrieval, calculation, and multi-step reasoning. Current tool-using agents usually expose the executed tool trajectory and the final answer, but they rarely specify which tool observation supports each generated claim. We call this missing claim-level dependency structure the provenance gap. The gap makes tool use hard to verify and hard to optimize, because useful evidence, redundant exploration, and unsupported reasoning are mixed in the same trajectory. We introduce TRACER, a framework for verifiable generative provenance in multimodal tool-using agents. Instead of adding citations after generation, TRACER generates each answer sentence together with a structured provenance record that identifies the supporting tool turn, evidence unit, and semantic support relation. Its relation space contains Quotation, Compression, and Inference, covering direct reuse, faithful condensation, and grounded derivation. TRACER verifies each record through schema checking, tool-turn alignment, source authenticity, and relation rationality, and then converts verified provenance into traceability constraints and provenance-derived local credit for reinforcement learning. We further construct TRACE-Bench, a benchmark for sentence-level provenance reconstruction from coarse multimodal tool trajectories. On TRACE-Bench, simply adding tools often introduces noise. With Qwen3-VL-8B, TRACER reaches 78.23% answer accuracy and 95.72% summary accuracy, outperforming the strongest closed-source tool-augmented baseline by 23.80 percentage points. Compared with tool-only supervised fine-tuning, it also reduces total test-set tool calls from 4949 to 3486. These results show that reliable multimodal tool reasoning depends on provenance-aware use of observations, not on more tool calls alone.

### 1. 核心问题与整体含义（研究动机和背景）
多模态大语言模型（MLLM）作为智能体，常通过调用外部工具（如OCR、搜索、计算器）解决复杂视觉任务。然而，现有智能体存在**“溯源鸿沟”（Provenance Gap）**：虽然公开了工具调用轨迹和最终答案，但无法明确答案中的每个断言（Claim）具体由哪次工具观察结果支撑。
*   **痛点**：这种模糊性导致推理过程难以验证（可能是幻觉或蒙对的），且难以优化（无法区分有用的工具调用与冗余的探索）。
*   **目标**：建立一种断言级的依赖结构，使生成的答案在证据来源上可追溯、可验证。

### 2. 方法论：TRACER 框架
TRACER 的核心思想是将溯源视为生成过程的一部分，而非事后解释。
*   **生成式溯源（Generative Provenance）**：模型在生成答案句子时，同步输出结构化的 JSON 记录，包含：
    *   **工具轮次（Tool Turn）**：指向具体的工具调用 ID。
    *   **证据单元（Evidence Unit）**：引用的具体文本或数据片段。
    *   **语义关系（Relation）**：定义为 **Quotation**（直接引用）、**Compression**（忠实压缩）或 **Inference**（逻辑推导）。
*   **可验证性检查**：通过模式检查、工具对齐、来源真实性及关系合理性四个维度对溯源记录进行自动化验证。
*   **溯源驱动的强化学习（RL）**：
    *   **奖励函数**：结合答案正确性（$R_{vqa}$）、溯源可追溯性（$R_{trace}$，硬约束）和工具引用效率（$R_{cite}$，惩罚冗余调用）。
    *   **局部信用分配（Local Credit）**：利用验证后的溯源信息，将奖励直接关联到产生有用工具查询的 Token 上，通过组相对策略优化（GRPO 变体）进行训练。

### 3. 实验设计
*   **数据集与基准**：构建了 **TRACE-BENCH**，基于 ToolVQA 轨迹重建。包含 14,183 条高质量溯源轨迹，涵盖 7 种工具（OCR、搜索、计算等）。
*   **评估指标**：答案准确率（Acc）、摘要准确率（SummAcc）、可追溯性准确率、溯源 F1 分数、工具调用次数及错误数。
*   **对比方法**：
    *   **闭源模型**：GPT-4o、Claude-3.5-Sonnet、Gemini-2.5-Pro（含工具增强版）。
    *   **开源模型**：Qwen2-VL、InternVL3.5、LLaVA 等。
    *   **基准线**：仅进行工具 SFT 的 Qwen3-VL-8B。

### 4. 资源与算力
*   **硬件**：使用了 **8 台 NVIDIA A100 GPU**。
*   **训练细节**：
    *   **SFT 阶段**：全参数微调，Batch Size 为 2，梯度累积 4 步，训练 2 个 Epoch。
    *   **RL 阶段**：基于 SFT 检查点，进行 200 步优化，每组采样 8 个候选输出。
    *   **精度**：使用 bfloat16 精度和 DeepSpeed ZeRO-2 优化。

### 5. 实验数量与充分性
*   **实验规模**：在 2,550 条测试集上进行了详尽测试。
*   **消融实验**：专门针对 $R_{cite}$（效率奖励）和 $R_{trace}$（溯源奖励）进行了消融，证明了两者对提升准确率和减少冗余调用的协同作用。
*   **充分性评价**：实验设计较为充分，不仅对比了任务成功率，还深入分析了工具使用的效率和溯源的忠实度。通过 LLM-as-a-judge（使用 Gemini-2.5-Pro）进行语义验证，增加了评估的客观性。

### 6. 主要结论与发现
*   **溯源提升性能**：TRACER-RL 在 Qwen3-VL-8B 上达到了 78.23% 的准确率，比最强的闭源工具增强基线（Gemini-2.5-Pro）高出 23.8 个百分点。
*   **减少冗余**：相比标准 SFT，TRACER 将工具调用次数从 4,949 减少到 3,486（约 **30%**），证明了模型学会了“按需调用”而非盲目探索。
*   **工具并非越多越好**：实验显示，未经溯源训练的模型在增加工具后，性能反而可能因噪声和规划错误而下降。

### 7. 优点
*   **细粒度可解释性**：将溯源精确到句子级和具体的语义关系，显著提升了智能体决策的透明度。
*   **闭环优化**：将溯源验证结果直接转化为 RL 的奖励信号，实现了“生成-验证-优化”的闭环。
*   **效率优化**：通过惩罚未被引用的工具调用，有效解决了智能体过度使用工具的资源浪费问题。

### 8. 不足与局限
*   **验证器偏差**：依赖 LLM-as-a-judge 进行溯源验证，可能存在模型偏见或提示词敏感性。
*   **工具集有限**：目前仅涵盖 7 种基础工具，对于更复杂的工业级工作流或更多模态（如视频、音频）的泛化性有待验证。
*   **因果性限制**：溯源记录反映的是外部依赖结构，并不等同于模型内部计算的完全因果解释。
*   **模型规模**：主要在 8B 规模模型上验证，更大规模模型（如 70B+）的扩展效应尚不明确。
