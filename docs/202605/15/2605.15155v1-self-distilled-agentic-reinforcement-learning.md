## 摘要
强化学习（RL）已成为大语言模型（LLM）智能体后训练的核心范式，但其轨迹级奖励信号仅能为长程交互提供粗粒度的监督。同策略自蒸馏（OPSD）通过引入来自增强了特权上下文（privileged context）的教师分支的密集 Token 级引导，对 RL 进行了补充。然而，将 OPSD 迁移到多轮对话智能体中存在挑战：复合的多轮不稳定性会使监督失效，而基于技能条件的特权引导需要非对称处理，因为教师的负面拒绝可能源于不完善的技能检索或利用。我们提出了 SDAR（自蒸馏智能体强化学习），它将 OPSD 视为一种门控辅助目标，同时保持 RL 作为主要的优化骨干。SDAR 将分离的 Token 级信号映射到 Sigmoid 门控中，加强了对教师认可的正差距（positive-gap）Token 的蒸馏，并软性地衰减了教师的负面拒绝。在 ALFWorld、WebShop 和 Search-QA 任务上，基于 Qwen2.5 和 Qwen3 系列模型的实验表明，SDAR 相比 GRPO 取得了显著提升（ALFWorld 提升 9.4%，Search-QA 提升 7.0%，WebShop-Acc 提升 10.2%），避免了原生 GRPO+OPSD 的不稳定性，并在不同模型规模下始终优于混合 RL-OPSD 基准。

## Abstract
Reinforcement learning (RL) has emerged as a central paradigm for post-training LLM agents, yet its trajectory-level reward signal provides only coarse supervision for long-horizon interaction. On-Policy Self-Distillation (OPSD) complements RL by introducing dense token-level guidance from a teacher branch augmented with privileged context. However, transferring OPSD to multi-turn agents proves problematic: compounding multi-turn instability destabilizes supervision, while skill-conditioned privileged guidance requires asymmetric treatment for negative teacher rejections may arise from imperfect skills retrieval or utilization. We introduce SDAR (Self-Distilled Agentic Reinforcement Learning), which treats OPSD as a gated auxiliary objective while keeping RL as the primary optimization backbone. SDAR maps detached token-level signals into a sigmoid gate, strengthening distillation on teacher-endorsed positive-gap tokens and softly attenuating negative teacher rejections. Across the Qwen2.5 and Qwen3 families on ALFWorld, WebShop, and Search-QA, SDAR substantially improves over GRPO (+9.4% on ALFWorld, +7.0% on Search-QA, +10.2% on WebShop-Acc), avoids the instability of naive GRPO+OPSD, and consistently outperforms hybrid RL--OPSD baselines across model scales.

### 1. 论文的核心问题与整体含义
论文关注的是**大语言模型（LLM）智能体在多轮交互场景下的后训练优化**。
*   **研究动机**：传统的强化学习（RL）主要依赖轨迹级的奖励信号，这对于长程交互任务来说过于粗糙（稀疏）。虽然“同策略自蒸馏（OPSD）”能提供密集的 Token 级引导，但在多轮智能体任务中直接应用会遇到两大难题：
    1.  **多轮不稳定性**：学生模型一旦偏离教师轨迹，误差会迅速复合，导致训练崩溃。
    2.  **特权引导的非对称信任**：教师模型通过“特权上下文”（如检索到的技能）获得增强，但如果检索到的技能质量差，教师给出的负面反馈（拒绝信号）可能是错误的。
*   **核心目标**：提出一种能够稳定结合 RL 奖励与 Token 级自蒸馏信号的框架，提升智能体在复杂任务中的表现。

### 2. 论文提出的方法论
SDAR 的核心思想是将 RL 作为主干优化器，而将 OPSD 视为一个**受控的辅助目标**。
*   **核心架构**：采用 GRPO（Group Relative Policy Optimization）作为基础 RL 算法，并并行运行一个带有特权信息（技能检索）的教师分支。
*   **关键技术：Token 级 Sigmoid 门控机制**：
    *   计算教师与学生在当前 Token 上的对数概率差距：$\Delta_t = \log \pi_T(y_t | s^+_t) - \log \pi_\theta(y_t | s_t)$。
    *   引入门控函数 $g_t = \sigma(\beta \Delta_t)$，其中 $\sigma$ 是 Sigmoid 函数，$\beta$ 是平滑参数。
    *   **非对称处理**：当教师更看好某个 Token 时（$\Delta_t > 0$），门控开启，强化蒸馏；当教师不看好时（$\Delta_t < 0$），门控自动衰减，降低该信号对训练的干扰。
*   **优化目标**：总损失函数为 $L = L_{GRPO} + \lambda \cdot L_{SDAR}$。其中 $L_{SDAR}$ 仅对学生生成的 Token 进行加权蒸馏，且对门控信号进行梯度截断（stop-gradient），确保训练稳定性。

### 3. 实验设计
*   **数据集/场景**：
    1.  **ALFWorld**：具身智能体文本环境，包含 6 类家务任务。
    2.  **Search-QA**：搜索增强问答，包含 NQ、TriviaQA、HotpotQA 等 7 个子集。
    3.  **WebShop**：真实的在线购物交互环境。
*   **基准模型**：Qwen2.5-3B/7B-Instruct 以及最新的 Qwen3-1.7B-Instruct。
*   **对比方法**：

    *   **训练方法**：GRPO、OPSD、Skill-GRPO（带技能的 RL）。
    *   **混合方法**：GRPO+OPSD（简单叠加）、Skill-SD、RLSD（现有的领先混合算法）。

*   **训练配置**：训练步数为 150 步。

*   **实验规模**：论文在 3 个不同领域的基准测试上进行了验证，涵盖了从 1.7B 到 7B 的不同模型规模，实验设计较为全面。
*   **消融实验**：非常充分。作者对比了不同的门控策略（熵门控、差距门控、Soft-OR）、不同的平滑系数 $\beta$、不同的蒸馏权重 $\lambda$ 以及不同的散度类型（Reverse KL, Forward KL, JSD）。
*   **鲁棒性测试**：专门针对“技能检索质量”做了实验，验证了即使在随机检索（低质量特权信息）下，SDAR 依然能保持优于基准 RL 的性能，证明了门控机制的有效性。

### 6. 论文的主要结论与发现
*   **性能飞跃**：SDAR 在所有任务上均显著优于 GRPO。在 7B 模型上，ALFWorld 提升 9.4%，WebShop 准确率提升 10.2%。
*   **稳定性解决**：成功解决了原生 OPSD 在多轮对话中容易崩溃的问题，尤其是在小模型（Qwen3-1.7B）上表现极其稳健。
*   **知识内化**：SDAR 训练后的模型在推理时**不需要**再挂载技能库，其性能甚至超过了那些在推理时带技能的对比方法，说明模型真正“学会”了特权知识。
*   **非对称信任的重要性**：实验证明，盲目信任教师的负面信号是有害的，通过 Sigmoid 门控进行软性过滤是保持性能的关键。

### 7. 优点
*   **设计优雅**：通过简单的 Sigmoid 门控解决了复杂的教师信号质量与多轮漂移问题，无需复杂的人工课程学习调度。
*   **即插即用**：作为辅助损失项，可以轻松集成到现有的 RL 框架（如 PPO, GRPO）中。
*   **泛化性强**：在不同规模的模型和完全不同的任务领域（具身、问答、购物）均表现一致。

### 8. 不足与局限
*   **依赖技能库（SkillBank）**：虽然论文证明了对检索质量的鲁棒性，但 SDAR 的效果仍高度依赖于预先构建的技能库质量，对于完全未知的领域，如何构建这些特权上下文未做深入讨论。
*   **计算开销**：虽然比全量教师分布蒸馏省钱，但训练时仍需运行教师分支的前向传播，增加了训练时的显存和计算负担。
*   **任务类型限制**：目前主要集中在文本和 Web 交互，尚未在视觉多模态智能体或更复杂的代码生成任务中进行验证。
