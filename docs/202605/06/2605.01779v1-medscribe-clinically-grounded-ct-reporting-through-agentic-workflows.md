## 摘要
视觉语言模型 (VLM) 在自动化放射科报告生成方面展现出潜力，但现有方法依赖于体积数据的全局嵌入压缩，这往往导致幻觉发现以及在 3D CT 成像中缺乏解剖学依据。我们介绍了 MedScribe，这是一个假设驱动的框架，它将报告生成重新定义为一个迭代的证据获取过程，而非单次编码任务。MedScribe 将报告生成建模为一个序列决策过程，其中大语言模型动态调用特定病理的诊断工具来提取局部体积特征。这些结构化特征被用于查询一个与特定病理文本证据对齐的多维检索空间。通过在综合之前显式地积累定量证据，该框架增强了细粒度的依据，并减少了无根据的陈述。在无需特定任务微调的情况下，与最先进的 2D 和 3D VLM 相比，MedScribe 在 CT-RATE 和 RadChestCT 数据集上提高了临床准确性、事实一致性和可解释性，证明了假设驱动推理对于可靠医学图像报告生成的价值。

## Abstract
Vision-language models (VLMs) have shown potential for automated radiology report generation, yet existing approaches rely on global embedding compression of volumetric data, often leading to hallucinated findings and limited anatomical grounding in 3D CT imaging. We introduce MedScribe, a hypothesis-driven framework that reformulates report generation as an iterative evidence acquisition process rather than a single-pass encoding task. MedScribe models reporting as a sequential decision process in which a large language model dynamically invokes pathology-specific diagnostic tools to extract localized volumetric features. These structured features are used to query a multidimensional retrieval space aligned with pathology-specific textual evidence. By explicitly accumulating quantitative evidence prior to synthesis, the framework enforces fine-grained grounding and reduces unsupported claims. Without task-specific fine-tuning, MedScribe improves clinical accuracy, factual consistency, and interpretability on CT-RATE and RadChestCT compared to state-of-the-art 2D and 3D VLMs, demonstrating the value of hypothesis-driven reasoning for reliable medical image reporting.

### MedScribe：通过智能体工作流实现具有临床依据的 CT 报告生成

#### 1. 核心问题与研究动机
*   **核心问题**：现有的视觉语言模型（VLM）在生成 3D CT 放射科报告时，通常采用全局嵌入压缩（如 ViT 编码器），将庞大的体积数据压缩为固定长度的向量。这种做法会导致“信息瓶颈”，造成细微病理特征丢失、解剖定位不准以及严重的“幻觉”现象（生成无事实依据的诊断）。
*   **研究背景**：3D CT 影像包含数以百计的切片，而放射科报告通常只描述显著的异常。这种监督信号的稀疏性使得端到端模型难以学习到精确的图像-文本对齐。

#### 2. 方法论
MedScribe 将报告生成从“单次编码任务”重构为“迭代的证据获取过程”，核心思想是**假设驱动的推理**。
*   **智能体工作流（Agentic Workflow）**：基于 ReAct（Reasoning and Acting）框架，使用大语言模型（LLM）作为核心推理引擎。
*   **关键技术细节**：
    *   **诊断工具调用**：LLM 动态调用专门的影像工具（如 TotalSegmentator）来提取特定解剖区域的结构化特征（如体积、Hounsfield 单位强度统计、空间坐标等）。
    *   **多维 RAG 检索空间**：利用提取的定量特征，在预先构建的参考数据库（基于 CT-RATE 数据集）中进行最近邻搜索（k-NN），检索出具有相似影像特征的病理描述文本片段（Snippets）。
    *   **两阶段运行模式**：
        1.  **MedScribe-Template**：从空白模板开始，通过工具调用逐步积累证据。
        2.  **MedScribe-VLM**：作为“自动审核员”，先获取基准 VLM 的初步报告，再调用工具验证并修正其中的发现。
*   **算法流程**：用户查询 -> LLM 推理 -> 调用工具提取特征 -> RAG 检索参考文本 -> 证据积累 -> 最终报告综合。

#### 3. 实验设计
*   **数据集**：
    *   **CT-RATE**：最大的公开 3D 胸部 CT-报告配对数据集（约 20,000 扫描用于构建 RAG 空间，1,304 扫描用于测试）。
    *   **RadChestCT**：包含 360 个样本，用于评估模型的泛化能力。
*   **Benchmark 与对比方法**：
    *   **对比模型**：包括 3D 原生模型 **CT-CHAT**，以及支持多图输入的 SOTA 模型 **Gemini 2.5 Flash**、**MedGemma 1.5-4B** 和 **VILA-M3**。
    *   **评估指标**：临床准确性（F1 分数，通过 RadBERT 分类器提取标签）、文本质量（BLEU, ROUGE, METEOR）以及新提出的**侧向性预测准确率（Laterality F1）**（针对胸腔积液的左右位置）。

#### 4. 资源与算力
*   **硬件**：实验在单张 **NVIDIA H100 GPU** 上运行。
*   **模型配置**：默认使用 **Llama 3.1-8B** 作为 LLM 后端（为了与 CT-CHAT 保持公平对比），同时也测试了 **Llama 3.3-70B** 以验证扩展性。
*   **耗时**：MedScribe-Template 在 H100 上的平均推理时间为 17.57 秒/扫描（不含分割耗时），相比之下 MedGemma 为 19.36 秒。

#### 5. 实验数量与充分性
*   **实验规模**：在两个大型数据集上进行了全面测试，涵盖 18 种病理类别。
*   **消融实验**：非常充分。作者分别验证了 RAG 的必要性、ReAct 框架的有效性、不同 k 值（检索邻居数）的影响，以及使用不同 LLM 后端的性能差异。
*   **客观性与公平性**：
    *   对 2D VLM 基准进行了切片数量（16 到 128 片）的消融，确保对比的是基准模型的最优性能。
    *   通过 RadChestCT 独立数据集验证，排除了标签循环论证的风险。
    *   进行了**分割误差敏感性分析**，客观讨论了底层工具出错对最终报告的影响。

#### 6. 主要结论与发现
*   **性能领先**：在无需任何特定任务微调的情况下，MedScribe 在临床准确性（Macro F1）上显著优于所有端到端 VLM 基准。
*   **细粒度定位**：在侧向性（左右位置）判断任务中，MedScribe 表现出极强的解剖定位能力，远超传统 VLM。
*   **可解释性**：报告的生成过程是透明的，每项结论都可以追溯到具体的定量特征和检索到的参考案例。
*   **扩展性**：使用更强大的 LLM（如 70B）能进一步提升推理能力和分类准确率。

#### 7. 优点
*   **解耦推理与感知**：通过工具调用解决了 3D 影像的“信息瓶颈”问题。
*   **零样本学习**：不需要昂贵的端到端微调，仅依靠现有的分割工具和 LLM 的推理能力。
*   **临床一致性**：通过显式的证据积累，极大地减少了幻觉，生成的报告更符合临床逻辑。
*   **模块化**：可以轻松扩展新的诊断工具以覆盖更多病理类型。

#### 8. 不足与局限
*   **依赖底层工具**：MedScribe 的准确性高度依赖于分割工具（如 TotalSegmentator）的质量。实验显示，如果肺部分割出错，相关病理的诊断准确率会大幅下降。
*   **病理覆盖范围**：性能增益与工具覆盖范围正相关。对于缺乏专用提取工具的病理（如裂孔疝、淋巴结病），模型提升有限。
*   **推理延迟**：由于涉及多次 LLM 调用和图像分割处理，其端到端延迟高于简单的单次推理模型。
*   **矛盾处理**：目前框架在处理工具输出与检索证据之间的冲突时，完全依赖 LLM 的隐式仲裁，缺乏显式的冲突解决机制。
