## 摘要
虽然长程移动端 GUI 智能体通常依赖于“思考-行动-观察”循环，但它们难以将持久的任务状态与瞬时的屏幕观察分离开来。随着执行历史的增长，这种纠缠带来了严重的上下文负担，导致智能体遗忘初始需求、产生进度幻觉，或反复与过时的界面交互。为了解决这一问题，我们引入了任务状态表示（TSR），这是一种无需训练的框架，能够显式地将任务状态与感官输入解耦。作为一种轻量级的外部封装，TSR 维护了三个结构化组件：全局指令摘要、子目标动态进度追踪器，以及感知状态转换的动作验证器。通过动作前后的视觉对比进行持续更新，TSR 在无需修改架构的情况下有效地引导智能体的推理。在四个移动端 GUI 基准测试上的实验验证了 TSR 的有效性，在复杂的跨应用和记忆密集型任务中，成功率绝对值提升了高达 12 个百分点。

## Abstract
While long-horizon mobile GUI agents typically rely on thought-action-observation loops, they struggle to separate persistent task states from transient screen observations. As execution histories grow, this entanglement imposes a severe context burden, causing agents to forget initial requirements, hallucinate progress, or repeatedly interact with stale interfaces. To address this, we introduce Task-State Representation (TSR), a training-free framework that explicitly decouples task state from sensory input. Acting as a lightweight external wrapper, TSR maintains three structured components: a global instruction summary, a dynamic progress tracker for subgoals, and a transition-aware action verifier. By continuously updating through pre- and post-action visual comparisons, TSR effectively guides the agent's reasoning without requiring architectural modifications. Experiments across four mobile GUI benchmarks validate TSR's effectiveness, yielding up to a 12 absolute point increase in success rate on complex cross-application and memory-intensive tasks.

### 2. 方法论
论文提出了 **TSR (Task-State Representation)** 框架，这是一种无需训练的外部包装器。
*   **核心思想**：引入一个独立的“状态更新器”（State Updater），在每一步操作后，通过对比动作前后的视觉差异来显式维护任务状态，并将其注入到智能体的输入提示词（Prompt）中。
*   **关键组件**：
    1.  **全局任务状态摘要（Global Summary）**：记录任务的持久语义和累积进度，防止意图衰减。
    2.  **进度追踪器（Progress Tracker）**：将任务分解为原子需求，维护“已完成里程碑”、“当前子目标”和“剩余需求”四个字段。
    3.  **转换感知焦点（Transition-Aware Focus）**：对比动作前后的截图（$o_{t-1}$ 和 $o_t$），验证动作有效性。若界面未更新，则引导智能体进行验证或刷新，而非盲目重复。
*   **工作流程**：
    *   **更新阶段**：状态更新器 $U_\phi$ 接收指令、旧状态、上一步动作及动作前后截图，输出更新后的结构化 JSON。
    *   **注入阶段**：将序列化后的状态块附加到智能体 $\pi_\theta$ 的 Prompt 中。该过程无需修改模型架构或进行微调。

### 6. 主要结论与发现
*   **性能提升**：在 MobileWorld 等长程任务中，成功率（SR）最高提升了 **12%**。在记忆密集型任务中也有 3-5% 的稳定提升。
*   **效率优化**：在某些任务中，TSR 帮助智能体以更少的步骤完成任务；而在复杂任务中，虽然步骤增加，但成功率大幅提升，说明 TSR 帮助智能体在困难面前坚持了下来。
*   **条件收益**：TSR 的有效性与任务复杂度正相关。在简单的单应用任务中，过度分解状态反而可能引入决策噪声，导致性能轻微下降。

### 7. 优点
*   **即插即用**：无需对底层模型进行任何微调或架构修改，易于部署到现有的智能体系统。
*   **逻辑清晰**：通过结构化的 JSON 显式解耦了“状态”与“观察”，直接针对长程任务的痛点（幻觉和遗忘）。
*   **闭环验证**：引入动作前后的视觉对比，为 Agent 提供了环境反馈的“闭环”，有效解决了 UI 延迟导致的死循环问题。

### 8. 不足与局限
*   **错误传播**：如果状态更新器（Updater）在某一步错误地标记了子目标已完成，智能体将基于错误的状态继续决策，导致错误累积。
*   **额外开销**：每步多出一次 LLM 调用，增加了推理延迟和成本。
*   **任务敏感性**：对于简单任务，TSR 可能属于“过度设计”，甚至可能因为过度分解任务而导致智能体在细节上浪费步数（如 Case Study 所示）。
