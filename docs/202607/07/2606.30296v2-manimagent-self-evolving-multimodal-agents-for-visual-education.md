## 摘要
多轮反思使基于大语言模型的智能体能够在单个任务中从失败中恢复，但每个任务仍然是一个孤立的片段：在某个任务的多轮反思中总结的经验教训在下一个任务开始前会被丢弃。我们在代码生成任务上研究了这一差距：智能体根据科学论文的章节，使用开源 Manim 库编写 Python 代码来渲染数学动画。我们提出了 ManimAgent，这是一种自我进化的多模态智能体，它通过一个完全由其自身任务流生成的双通道情境记忆库（Episodic Memory Bank）跨任务携带反思经验，无需权重更新，也无需人工种子。在每个动画收敛后，视觉语言模型会对渲染的关键帧进行评分；生成的信号填充到两个通道中：正向通道 M+ 将成功原理存储为软“参考示例”（Reference Examples），负向通道 M- 将经过验证的失败模式存储为硬“已知陷阱”（Known Pitfalls）。在针对无记忆、等预算检索增强生成以及乱序记忆基线的固定探针评估中，随着记忆容量的增长，盲测人类 Pass@1 指标上升，而反思轮数下降。我们将发布代码、冻结的记忆快照以及任务流。

## Abstract
Multi-round reflection lets agents built on large language models recover from failures within a single task, but each task remains an isolated episode: lessons learned across many reflection rounds on one task are discarded before the next begins. We study this gap on a code-generation task: from a scientific paper section, the agent writes Python in the open-source Manim library to render a mathematical animation. We present ManimAgent, a self-evolving multimodal agent that carries reflection experience across tasks through a dual-channel Episodic Memory Bank grown entirely from its own task stream, with no weight updates and no human seeds. After each animation converges, a vision-language model scores the rendered keyframes; the resulting signals populate a positive channel M+ that stores success rationales as soft Reference Examples, and a negative channel M- that stores validated failure patterns as hard Known Pitfalls. On a fixed-probe evaluation against no-memory, matched-budget retrieval-augmented generation, and shuffled-memory baselines, blind human Pass@1 rises and reflection rounds fall as memory size grows. We will release the code, frozen memory snapshots, and the task stream.

### 1. 核心问题与整体含义（研究动机和背景）
*   **核心问题**：现有的基于大语言模型（LLM）的智能体在处理复杂任务（如生成 Manim 数学动画代码）时，虽然能通过“单任务内反思”（Intra-task Reflection）修复错误，但存在**跨任务遗忘（Cross-task Forgetting）**。即智能体在任务 A 中学到的布局、语法或逻辑教训，在进入任务 B 时会被完全丢弃，导致重复犯错并浪费大量 Token。
*   **研究背景**：Manim 是一个用于解释数学和科学概念的 Python 库。将科学论文转化为动画需要极高的逻辑准确性和视觉审美，这对智能体的长期记忆和经验积累提出了挑战。

### 2. 方法论：核心思想与关键技术
ManimAgent 的核心是一个**双通道情节记忆库（Episodic Memory Bank, EMB）**，其特点是无需权重更新、无需人工标注、完全自进化。
*   **双通道设计**：
    *   **正向通道 ($M^+$)**：存储“成功原理”。当 VLM 评分 $\ge 85$ 时，将代码和成功逻辑提炼为“参考示例”（Reference Examples），作为软引导。
    *   **负向通道 ($M^-$)**：存储“已知陷阱”。记录从失败到成功的转换过程（如修复了崩溃或视觉遮挡），提炼为“硬约束规则”，防止重蹈覆辙。
*   **关键流程**：
    1.  **检索**：根据当前任务，从 $M^+$ 和 $M^-$ 中检索最相关的经验。
    2.  **生成与修复**：Coder 结合经验生成代码；若运行崩溃，由文本 Reviewer 引导修复。
    3.  **视觉反思**：渲染成功后，由视觉语言模型（VLM）对关键帧进行多维度评分（逻辑流、布局、准确性）。
    4.  **记忆固化**：任务结束后，由专门的“蒸馏智能体”将执行轨迹转化为自然语言教训，存入 EMB。
*   **写入门控**：并非所有尝试都存入记忆。$M^+$ 要求高分，$M^-$ 要求有显著的质量提升（分差 $\ge 5$），以确保记忆的质量。

### 3. 实验设计
*   **数据集**：自建科学论文章节动画数据集，涵盖计算机科学、数学、物理、量子力学、经济学五个领域。分为记忆构建集（39个任务）、固定探针集（33个任务）和跨测试集（40个任务）。
*   **评估协议**：采用**固定探针（Fixed-probe）**评估，即在不同规模的冻结记忆快照（K=0, 50, 100, 200）上运行相同的测试任务，以排除任务顺序的影响。
*   **对比方法（Baselines）**：
    1.  **VLM Reflection Only**：仅有单任务反思，无记忆。
    2.  **Manim-code RAG**：检索静态的、人工编写的 Manim 文档和示例库。
    3.  **Random EMB**：打乱记忆内容与任务的对应关系。
*   **核心指标**：盲测人类 Pass@1（首轮成功率）、平均反思轮数、人类评分（1-5分）。

### 4. 资源与算力
*   **模型使用**：全线使用 **GPT-5.5 家族**模型（包括文本智能体和 VLM 评审员）。消融实验中使用了 Step-3.7-Flash 作为弱 VLM 对比。
*   **算力消耗**：文中未明确提及具体的 GPU 训练算力（因为是 Zero-shot + RAG 架构，无需训练），但给出了推理成本：
    *   每个任务平均消耗 **36K-38K LLM Tokens** 和 **20K-23K VLM Tokens**。
    *   单个任务的端到端耗时约 **19-31 分钟**（含渲染时间）。

### 5. 实验数量与充分性
*   **实验规模**：进行了 7 组基线对比实验和 9 组消融实验（涵盖通道隔离、写入门控、检索深度、模型强度等）。
*   **充分性**：实验设计非常严谨。通过固定快照评估解决了智能体实验中常见的“测试集污染”和“任务顺序偏差”问题。
*   **客观性**：引入了 **54 名人类评测员**进行双盲评分，并计算了评分者间的一致性（Fleiss' κ），确保了最终评价指标（Pass@1）的客观性，而非仅仅依赖 VLM 的自我评分。

### 6. 主要结论与发现
*   **记忆的增长效应**：随着 EMB 规模从 0 增长到 200，人类 Pass@1 从 62.0% 提升至 **84.9%**，反思轮数从 12.2 降至 **6.5**。
*   **超越静态 RAG**：自生成的 EMB 在 K=200 时全面超越了基于人工文档的 RAG 基线，证明了“从自身错误中学习”比“看教科书”更有效。
*   **通道分工**：消融实验显示，$M^+$ 主要提升初始生成的质量，而 $M^-$ 显著降低了修复成本（反思轮数）。

### 7. 优点（亮点）
*   **双通道机制**：模仿人类教育者的思维，既有“怎么做”的正向模板，又有“别踩坑”的负向清单。
*   **自进化闭环**：完全不需要人工干预或初始种子数据，实现了真正的闭环学习。
*   **评估严谨**：固定探针协议和盲测人类评估为 Agent 领域的实验设计树立了高标准。

### 8. 不足与局限
*   **VLM 奖励噪声**：实验发现 VLM 评分与人类评分的一致性较低（相关性接近 0），这意味着 VLM 作为一个“不完美的老师”，可能会将错误的偏好固化到记忆中。
*   **成本高昂**：每个任务半小时的耗时和数万 Token 的消耗，限制了其在大规模实时教学中的应用。
*   **领域局限**：目前仅在 Manim 库和英文科学论文上验证，尚未测试其在 D3.js 或其他可视化工具上的泛化能力。
*   **记忆冗余**：目前记忆库是单调增长的，缺乏去重和淘汰机制，长期运行可能导致检索效率下降。
