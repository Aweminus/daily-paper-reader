## 摘要
视觉语言导航（VLN）旨在使具身智能体能够通过遵循自然语言指令在复杂环境中进行导航。近期的研究方法通过构建语义空间地图并利用大语言模型（LLMs）进行推理和决策。尽管取得了这些进展，现有系统仍缺乏实例级物体细节以及对多样化用户查询的鲁棒性，限制了在复杂室内环境中的可靠导航。为了解决这些局限性，我们提出了“实例增强语义地图”（Instance-Enriched Semantic Maps），这是一个具有三个核心贡献的统一框架：(1) 实例级 2.5 维（2.5D）丰富信息映射，通过开放词汇全景分割从彩色和深度观测中构建地图，保留垂直区分度并捕捉细小物体，同时存储多样化的语义属性和富含房间级上下文的自然语言描述。(2) 基于 LLM 目标选择的鲁棒查询处理，通过在特定类型的专家模型之间动态路由查询，并通过得分级融合整合其输出，从而在多样化的查询表述中实现一致的目标选择。(3) 存储高效的语义表示，与三维（3D）场景图方法相比，存储量减少了约 96%，同时保留了足够的导航空间信息。所提出的 2.5D 表示在预测归一化曲线下面积（AUC）方面优于 3D 基准 27% 以上。在导航实验中，与基准相比，我们的方法在多种查询类型下的物体检索率提高了 17% 以上，导航成功率提高了 23% 以上。项目页面见 https://rcilab.github.io/iesm_vln。

## Abstract
Visual Language Navigation (VLN) aims to enable an embodied agent to navigate complex environments by following natural language instructions. Recent approaches build semantic spatial maps and leverage Large Language Models (LLMs) for reasoning and decision making. Despite these advances, existing systems lack instance-level object detail and robustness to diverse user queries, limiting reliable navigation in complex indoor environments. To address these limitations, we propose Instance-Enriched Semantic Maps, a unified framework with three key contributions: (1) Instance-level two-and-a-half-dimensional (2.5D) rich information mapping that constructs maps from color and depth observations via open-vocabulary panoptic segmentation, preserving vertical distinctions and capturing small objects, while storing diverse semantic attributes and natural language captions enriched with room-level context. (2) Robust query processing via LLM-based target selection, which dynamically routes queries across type-specialized experts and integrates their outputs through score-level fusion, enabling consistent goal selection across diverse query formulations. (3) Storage-efficient semantic representation that achieves approximately 96% reduction compared to three-dimensional (3D) scene-graph approaches while preserving sufficient spatial information for navigation. The proposed 2.5D representation outperforms the 3D baseline by over 27% in prediction-normalized Area Under the Curve (AUC). In navigation experiments, our method achieves over 17% improvement in object retrieval and over 23% in navigation success compared to the baseline across diverse query types. The project page is available at https://rcilab.github.io/iesm_vln.

### 1. 核心问题与整体含义（研究动机和背景）
视觉语言导航（VLN）要求机器人根据自然语言指令在复杂室内环境中移动。现有的语义地图表示存在两个主要矛盾：
*   **表示维度的权衡**：2D 地图计算高效但会丢失垂直信息（如书架上叠放的不同物体会混淆）；3D 地图（如场景图或体素）虽然精确，但存储开销巨大，难以扩展到大规模或长期任务。
*   **语义理解的局限**：现有系统往往只存储类别标签，缺乏实例级的细节（如颜色、材质、功能描述），导致其在面对复杂、属性相关或抽象的查询（如“去那个最舒服的能坐三人的地方”）时表现不佳。

本文提出了**实例增强语义地图（IESM）**框架，旨在通过 2.5D 表示平衡存储与精度，并通过大语言模型（LLM）驱动的专家融合机制提升对多样化查询的鲁棒性。

### 2. 方法论：核心思想与关键技术
该框架由四个核心模块组成：
*   **实例级 2.5D 开放词汇映射**：
    *   利用 **SEEM** 模型进行全景分割，提取实例掩码和特征。
    *   **2.5D 表示**：每个网格单元（Grid Cell）不只存储一个标签，而是存储多个垂直堆叠的实例索引。这保留了 Z 轴上的结构差异，同时避免了 3D 点云的冗余。
    *   通过几何（重叠率）和语义（余弦相似度）的双重加权融合，实现跨帧的实例关联。
*   **房间级语义分割**：
    *   利用直线检测器（LSD）识别墙壁、门等结构边界，生成房间分割掩码。
    *   结合 **CLIP** 的像素级语义预测，通过区域内投票（Majority Vote）为每个房间分配稳定的语义标签（如“厨房”、“卧室”）。
*   **实例描述生成（Captioning）**：
    *   利用 **LLaMA 3.2 Vision** 对每个实例的多视角图像进行视觉属性提取（颜色、材质、形状）。
    *   利用 **GPT-4** 将冗余信息压缩成精炼的自然语言描述，并关联房间上下文。
*   **多类型专家融合检索（MTEFR）**：
    *   **Gate LLM**：分析用户查询，动态分配四个专家的权重。
    *   **四个专家 LLM**：分别针对“物体类别”、“房间上下文”、“视觉描述”和“抽象意图”进行独立排名。
    *   **得分级融合**：结合加权总分（Sum Score）和峰值分数（Peak Score），通过自适应调度算法确定最终目标实例。

### 6. 主要结论与发现
*   **存储极度高效**：2.5D 表示比 3D 场景图（HOV-SG）减少了约 **96%** 的存储空间，比 2D 的 VLMaps 减少了约 92%。
*   **映射精度更高**：在预测归一化 AUC 上比 3D 基准提升了 **27%** 以上，尤其在保留小物体方面表现优异。
*   **导航鲁棒性强**：在处理包含描述和抽象意图的复杂查询时，物体检索率提升了 17%，导航成功率提升了 23%。
*   **专家融合的必要性**：实验证明，仅提供丰富的描述信息而不使用 MTEFR 路由机制，性能提升有限，证明了“按需分配专家”的有效性。

### 7. 优点（亮点）
*   **创新的 2.5D 表示**：巧妙地解决了 2D 丢失垂直信息和 3D 存储过大的矛盾，非常适合资源受限的嵌入式机器人平台。
*   **深度的语义增强**：通过 LLM 生成实例 Caption，使机器人能理解“材质”、“舒适度”等高层语义，而非仅仅是“椅子”这种物理标签。
*   **查询自适应检索**：MTEFR 机制模仿了人类处理信息的方式，能够根据指令侧重点动态调整推理逻辑。

### 8. 不足与局限
*   **计算延迟**：系统依赖多个大型模型（SEEM, LLaMA, GPT-4）的级联推理，实时性可能受限，文中也提到了未来需探索轻量化蒸馏。
*   **房间分割依赖物理隔断**：基于直线检测（LSD）的方法在开放式空间（Open-plan, 如客餐厅一体）中容易失效，无法准确划分功能区。
*   **抽象查询的挑战**：虽然比基准好，但在极度模糊的抽象查询下（如“找个存东西的地方”），系统仍可能在多个相似功能物体间产生歧义。
*   **环境假设**：目前主要在单层室内环境验证，多层建筑的扩展性有待进一步研究。
